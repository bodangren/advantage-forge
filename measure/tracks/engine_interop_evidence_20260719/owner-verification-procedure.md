# Owner Verification Procedure: Phase S3

The owner should verify the following before accepting
`Phase S3: Gate Delivery Claims on Interchange Evidence`.

1. Review `public-mcp-replay-verification.md`,
   `clone-replay-verification.md`, and `s3-gate-verification.md`.
2. Confirm the accepted boundary is public stdio MCP only: 16 advertised tools,
   17 successful calls, exact revision pinning, canonical manifest retrieval,
   bounded chunk retrieval, and no Pixel import of Forge source or handlers.
3. Confirm the two final clone replays produced identical raw discovery,
   manifest, chunk, PNG, GLB, and workflow-evidence bytes without network use or
   copied `.forge` state.
4. Inspect the eight-direction contact sheet at actual size. Confirm the current
   adventurer is acceptable only as an interchange placeholder. The thin E/W
   silhouettes are recorded quality debt and must not be interpreted as final
   theme-pack approval.
5. Confirm Pixel validates the real raw discovery, manifest, all 11 chunks, all
   10 reconstructed records, and the `education-app-pack-profile/v1` handoff
   while live pack ingestion remains gated.
6. Confirm the claim remains limited: no temporal animation, atlas, finished
   educational-app pack, final-art quality, or game-engine compatibility is
   accepted by this phase.
7. Respond with explicit approval or rejection. If rejecting, name the failed
   contract or visual condition.

After explicit approval, Measure still requires owner authorization for the
checkpoint commit and Git note. Without that authorization the phase and track
remain open.
