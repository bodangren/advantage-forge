## 3. Code quality observations

- **Process discipline is excellent.** Every phase follows contract → failing test → implementation → docs/gates, with red-run evidence noted in commit annotations. Verification dossiers include reproducible owner procedures with concrete revision IDs.
- **`semantic-diff.ts` is well built**: recursive keyed-collection diffing with deterministic ordering and stable JSON-path output. The `collectionKey` heuristic (`id`/`partId`/`slot`/`materialId`) is mildly fragile — a future keyed array with a different key silently degrades to index-based diffing.
- **`tools()` in `capabilities.ts` silently filters unregistered names** (`src/tools/capabilities.ts:16`). A typo in a fact's evidence would just vanish from the report instead of failing a test. Throwing on an unknown name would make the "evidence cites only executable public tools" guarantee self-enforcing.
- **Some dead defensive code**: `accessoryFact` accepts only literal `'equipment.sword' | 'equipment.shield'` types yet carries an `unsupported` branch for unregistered templates — this is where the 71.42% branch coverage goes. Either widen the type or drop the branch.
- **Declared facts are hand-authored prose.** Reference facts and tool/template/profile IDs are derived from registered sources, but the 16 `declaredFacts` summaries and guidance are maintained by hand. The drift tests protect the generated catalog, not the truthfulness of the prose itself — acceptable for now, worth watching as tools evolve.
- Minor: `compareText` is duplicated across three modules; `inspectAsset` builds all five sections (including a full assembly evaluation) even when one page of one section is requested — fine at 19 parts, but it's O(everything) per read; `portFor` throws a bare `Error` on a dangling connection rather than returning a structured issue (defensible as an invariant violation since documents are schema-validated on write).
- Pagination edge case: offset validation is skipped when a section is empty, so `offset: 50` on an empty section returns an empty page instead of `INVALID_VALUE`. Harmless but inconsistent with the non-empty behavior.
