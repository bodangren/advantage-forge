# P2 map build: shared rules

You build ONE new Chibi Quest map from a mockup image. A map is a list of placements
(`Place`: `asset`, `at` [x, y, z] in meters, `yaw` degrees around Y with 0 facing south (+Z),
optional `scale`). North is -Z, east is +X. Ground tiles are 2 m x 2 m slabs 0.3 m thick with
the walkable top at y = 0; props and characters stand at y = 0 unless they sit on a surface.
Target score: 7.0 of 10 against the mockup (P2 bar). Record your score honestly.

## Files you write (and only these)

- `scripts/design-<slug>.mjs`: the generator. Model it on `scripts/design-old-oak-clearing.mjs`
  (outdoor, data tables, ASCII map, tally) or `scripts/design-sunken-vault.mjs` (walls, rooms).
  It writes `scenes/maps/<slug>.ts` and `docs/map-mockups/<slug>.md` (layout, tally, notes).
- `scenes/maps/<slug>.ts` is GENERATED. Never edit it by hand. Its shape:
  ```ts
  // GENERATED by scripts/design-<slug>.mjs — edit the generator, not this file.
  import type { Place } from '../chibi-quest.js';
  export function places(): Place[] { return [ /* ... */ ]; }
  ```
- Never edit `src/`, `assets/`, `docs/fantasy-world-scene-blueprints.tsv`, or any other map.
- Never run git (no add, commit, stash, checkout). The orchestrator commits.

The viewer picks your map from `?scene=<slug>`. Lighting (dark cave, warm interior, or day) is
already set by the orchestrator for your slug; do not change it.

## Pieces

Use only existing assets: `ls assets/` (a name is `assets/<name>.ts`). A piece shows in the
viewer only if `out/<name>/<name>.glb` exists. Check each name you use with `ls out/<name>/`.
If you need a piece that does not exist, place nothing for it and list it in your report as
"missing: <name> - <what it is>". Never build assets. Ground tiles: grass-ground, dirt-ground,
forest-ground, stone-ground, desert-ground, snow-ground, marsh-ground, meadow-ground, floor,
floor-cracked, wood-floor, stone-floor, tile-floor, cobble-floor, dirt-floor, grass-floor.
Also: river-*, footpath-*, dirt-road-*, cobble-road-*. Walls: wall, stone-wall, timber-wall,
brick-wall, plaster-wall (+ -door, -window), wall-corner, wall-gate, wall-alcove, rampart,
city-wall. Check the real height and footprint of a piece in `assets/<name>.ts` before you place it.

Piece count: 150 to 320 placements. Every piece stands on ground or on a surface; nothing
floats, nothing sinks into a wall, nothing stands outside the map edge. The map has one focal
object, two or three zones with one story each, a clear path, and edge dressing.

## Shots (the scene server runs on port 5232)

```bash
FORGE_SHOT_BASE=http://127.0.0.1:5232/hamlet.html node scripts/shoot-map.mjs <outdir> \
  '<slug>-3q=scene=<slug>&clean&az=35&el=44&dist=<D>&tx=0&tz=0' '<slug>-top=scene=<slug>&clean&az=0&el=86&dist=<D2>&tx=0&tz=0'
```

`<D>` and `<D2>` come from your brief. One shot takes about a minute. The script prints
`shot <name> <N> pieces.` and any page error (a 404 is a missing GLB). Work shots go to
`/tmp/claude-1000/maps-<slug>/`. Name each shot `<slug>-3q` and `<slug>-top` (never `3q` or `top`: agents share the folder). At the end, shoot the final views into
`docs/map-mockups/<slug>-3q.png` and `docs/map-mockups/<slug>-top.png`.

## How to work

1. Read this file, your brief, and the mockup image (`docs/map-mockups/<slug>.jpg`).
2. Read one model generator, then plan on paper: grid size, zones, focal object, path, dressing.
3. Write the generator, run it, shoot, compare with the mockup. Fix the largest difference. Shoot.
4. Check floating, sinking, and out-of-bounds pieces.

Budget: at most 6 image looks (the mockup counts) and about 40 tool calls. Stop when you reach
7.0 or the budget ends.

## Report (at most 12 lines)

Files written, final piece count, your score of 10, the three largest remaining differences,
missing pieces, and the number of image looks.
